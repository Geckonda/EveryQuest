# Ежеквестик — план MVP

Oct 17, 2026 · @Alex

## Концепция

Веб-органайзер (PWA для телефона и ПК), где задачи — это квесты с наградой во внутренней валюте, а развлечения — траты, которые нужно оплатить. Есть монеты — иди развлекайся, нет — выполняй квесты. Любишь кататься — люби и саночки возить.

Принципы:

- **Инструмент учёта, а не надзиратель.** Приложение честно считает монеты, а не проверяет пользователя. Злоупотребления — ответственность пользователя.
- **Всё кастомизируется.** Категории, тиры, траты, награды и штрафы настраивает сам пользователь. При регистрации выдаются шаблоны по умолчанию.
- **Один человек — один аккаунт.** Совместных квестов нет. Аудитория — автор и небольшой круг друзей.
- **Простое сейчас, задел на потом.** Таймер трат и уведомления не реализуются в MVP, но схема к ним готова.

## Стек

Vue 3 на фронте, FastAPI + PostgreSQL на бэке, всё в Docker Compose.

| Слой | Технология | Зачем |
| --- | --- | --- |
| Фронтенд | Vue 3 + Vite + TypeScript | Основа SPA |
| Стейт и роутинг | Pinia, Vue Router | Стандарт для Vue 3 |
| UI | Naive UI / PrimeVue (выбрать одну) | Готовые компоненты, не верстать с нуля |
| Установка на устройства | vite-plugin-pwa | Ставится как приложение на телефон и ПК, позже — Web Push |
| Бэкенд | FastAPI + Pydantic | API и валидация |
| ORM и миграции | SQLAlchemy 2.0 + Alembic | Модели и версии схемы |
| База | PostgreSQL | Транзакции, `SELECT … FOR UPDATE` |
| Авторизация | JWT (access + refresh), argon2 для паролей | Регистрация и вход |
| Фоновые задачи | APScheduler внутри FastAPI | Штрафы и генерация повторяющихся квестов |
| Окружение | Docker Compose | Фронт, бэк и база одной командой |

Ограничение: Web Push на iOS работает только для PWA, добавленного на домашний экран.

## Схема БД

Семь таблиц. Баланс хранится в `users` как кэш, но каждое изменение фиксируется в `transactions`. Все даты — в UTC.

```sql
users
  id PK, email UNIQUE, username, password_hash,
  balance INT DEFAULT 0,          -- может быть отрицательным
  timezone TEXT,                  -- IANA, напр. 'Europe/Saratov'
  penalty_multiplier NUMERIC(4,2) DEFAULT 1,  -- штраф по умолчанию = награда × множитель
  created_at

tiers
  id PK, user_id FK, name,        -- 'I'..'V'
  level INT,                      -- 1–5, для сортировки
  default_reward INT,             -- штрафа у тира нет, см. users.penalty_multiplier
  color, is_archived

categories
  id PK, user_id FK, name, description, color, is_archived

recurring_quests                  -- шаблон повторяющегося квеста
  id PK, user_id FK, category_id FK NULL, tier_id FK,
  name, description, reward INT, penalty INT,
  frequency,                      -- daily | weekly | monthly
  interval INT DEFAULT 1,         -- каждые N периодов
  days_of_week INT[] NULL,        -- для weekly: 1–7
  day_of_month INT NULL,          -- для monthly: 1–31 (31 = последний день)
  due_time TIME DEFAULT '23:59',  -- локальное время пользователя
  start_date DATE, end_date DATE NULL,
  is_active BOOL, created_at

quests                            -- конкретный квест (разовый или экземпляр)
  id PK, user_id FK, category_id FK NULL, tier_id FK,
  recurring_quest_id FK NULL,
  period_date DATE NULL,          -- за какой день/период экземпляр
  name, description, reward INT, penalty INT,
  status,                         -- active | completed | failed | archived
  created_at, due_at NULL,
  closed_at NULL,                 -- когда закрыт; у проваленного по сроку = due_at
  close_reason NULL,              -- completed | expired | abandoned | archived (CHECK: согласовано со status)
  penalty_applied BOOL DEFAULT false
  UNIQUE (recurring_quest_id, period_date)

rewards                           -- «траты»
  id PK, user_id FK, name, description, price INT,
  duration_minutes INT NULL,      -- есть — при покупке стартует сеанс
  is_archived, created_at

transactions
  id PK, user_id FK,
  amount INT,                     -- +награда, −штраф, −покупка
  type,                           -- quest_reward | penalty | purchase | manual
  quest_id FK NULL, reward_id FK NULL,
  balance_after INT, created_at

reward_sessions                   -- идущая трата: «ТикТок на 20 минут»
  id PK, user_id FK, reward_id FK, transaction_id FK UNIQUE,
  name,                           -- название на момент заказа
  started_at, ends_at,
  finished_at NULL                -- закончили раньше срока
```

Решения по схеме:

- **Награда и штраф квеста копируются из тира при создании.** Изменение тира не трогает уже созданные квесты.
- **Шаблоны копируются при регистрации.** Пользователь получает свои строки тиров I–V и стандартных категорий и редактирует их свободно.
- **Удаления нет, есть архивация.** История транзакций остаётся целой.
- **`UNIQUE (recurring_quest_id, period_date)`** не даёт планировщику создать экземпляр дважды.
- **Индексы:** `quests (status, due_at)` для поиска просрочек, `transactions (user_id, created_at)` для истории.

## Повторяющиеся квесты

Повторяющийся квест — это шаблон (`recurring_quests`), по которому планировщик создаёт обычные квесты-экземпляры. Каждый экземпляр живёт независимо: его выполняют, проваливают и штрафуют как разовый квест.

Как считается период (в часовом поясе пользователя):

| frequency | Когда создаётся экземпляр | `due_at` |
| --- | --- | --- |
| daily | Каждые `interval` дней с `start_date` | Тот же день, `due_time` |
| weekly, `days_of_week` заданы | В каждый отмеченный день недели | Тот же день, `due_time` |
| weekly, `days_of_week` пусто | Раз в неделю, в понедельник | Воскресенье, `due_time` |
| monthly | В `day_of_month` (или 1-е, если не задан) | Последний день месяца или тот же день, `due_time` |

Правила:

- **Экземпляр создаётся в начале периода**, а при создании шаблона — сразу за текущий период.
- **Пропущенный экземпляр не блокирует следующий.** Он уходит в `failed` со штрафом, а новый создаётся по расписанию.
- **Изменение шаблона влияет только на будущие экземпляры.** Уже созданный экземпляр не меняется.
- **Пауза** — это `is_active = false`: новые экземпляры не создаются, текущий активный остаётся.

## Бизнес-правила

Каждая операция с монетами — одна транзакция БД: смена статуса, запись в `transactions` и изменение `balance` проходят вместе или не проходят вовсе.

**Баланс и покупки**

- Баланс может уйти в минус, но только от штрафов.
- Покупка разрешена, если `balance >= price`. В минусе купить ничего нельзя.
- Перед покупкой строка пользователя блокируется (`SELECT … FOR UPDATE`), чтобы два устройства не потратили одни монеты.

**Квесты**

- Выполнить можно только `active` квест: `status = completed`, `closed_at = now`, `balance += reward`.
- Провалить вручную (`POST /quests/{id}/fail`) можно только `active` квест с непрошедшим сроком: `status = failed`, `close_reason = abandoned`, штраф списывается полностью (в минус можно).
- Выполнение просроченного, но ещё не обработанного квеста запрещено: он уже провален.
- Отмена выполнения — не в MVP. Ошибку правит ручная транзакция `manual`.

**Категории и тиры**

- Категорию нельзя архивировать, пока в ней есть `active` квесты или активные шаблоны повторяющихся квестов. API отвечает 409 со списком мешающих квестов.
- Для тиров то же правило.

**Фоновые задачи (APScheduler, раз в 5 минут)**

1. **Штрафы.** Найти `active` квесты с `due_at < now` и `penalty_applied = false`. Для каждого: `status = failed`, `penalty_applied = true`, `balance -= penalty`, запись `penalty`.
2. **Генерация.** Для каждого активного шаблона, у которого начался новый период по времени пользователя, создать экземпляр. Дубликаты отсекает уникальный индекс.

Обе задачи идемпотентны: повторный запуск ничего не ломает. Это важно после перезапуска сервера.

## API

REST под префиксом `/api/v1`. Все ресурсы, кроме auth, требуют JWT и видят только данные текущего пользователя.

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/auth/register` | Регистрация + копирование шаблонов тиров и категорий |
| POST | `/auth/login` | Выдаёт access и refresh токены |
| POST | `/auth/refresh` | Новый access токен |
| GET / PATCH | `/me` | Профиль, баланс, часовой пояс |
| GET / POST | `/tiers` | Список, создание |
| PATCH | `/tiers/{id}` | Изменение, архивация (409, если есть активные квесты) |
| GET / POST | `/categories` | Список, создание |
| PATCH | `/categories/{id}` | Изменение, архивация (409, если есть активные квесты) |
| GET / POST | `/quests` | Список с фильтрами `status` (можно несколько), `category_id`, `tier_id`, пагинация; активные — без лимита; создание разового |
| PATCH | `/quests/{id}` | Изменение активного квеста |
| POST | `/quests/{id}/complete` | Выполнить, начислить награду |
| POST | `/quests/{id}/fail` | Провалить вручную, списать штраф |
| GET / POST | `/recurring-quests` | Шаблоны повторяющихся квестов |
| PATCH | `/recurring-quests/{id}` | Изменение, пауза, архивация |
| GET | `/calendar?start=&end=` | Квесты со сроком в диапазоне (до 62 дней) и прогноз будущих экземпляров повторяющихся |
| GET / POST | `/rewards` | Траты: список, создание |
| PATCH | `/rewards/{id}` | Изменение, архивация |
| POST | `/rewards/{id}/purchase` | Купить (400, если монет не хватает); у траты с длительностью — стартует сеанс |
| GET | `/reward-sessions/active` | Идущие траты |
| POST | `/reward-sessions/{id}/finish` | Закончить трату раньше срока |
| GET | `/transactions` | История с пагинацией |
| GET | `/transactions/today` | Итог дня по часовому поясу пользователя |
| POST | `/transactions/manual` | Ручная корректировка баланса |

## Этапы разработки

Семь этапов. Каждый заканчивается тем, что можно потрогать руками.

1. **Каркас.** Монорепо `frontend/` + `backend/`, Docker Compose с Postgres, Alembic, первая миграция, линтеры.
   - [x] Проект поднимается одной командой
2. **Аккаунты.** Регистрация, вход, refresh, копирование шаблонов при регистрации. На фронте — страницы входа и регистрации, guard в роутере.
   - [x] Можно зарегистрироваться и увидеть свои тиры и категории
3. **Справочники.** CRUD тиров, категорий и трат, архивация с проверкой 409.
   - [x] Можно настроить всё под себя
4. **Квесты и экономика.** Разовые квесты, выполнение, покупка трат, журнал транзакций, баланс в шапке.
   - [x] Полный цикл: заработал → потратил
5. **Повторяющиеся квесты и штрафы.** Шаблоны, планировщик генерации и штрафов, тесты на часовые пояса и границы месяцев.
   - [x] Ежедневный квест появляется сам, просрочка списывает монеты
6. **PWA и деплой.** Манифест, иконки, установка на телефон, деплой на VPS, HTTPS.
   - [ ] Приложением пользуешься ты и друзья
7. **Обучение новичка.** Приветственный свиток, обучающие квесты с автозакрытием, подсказки, справочник. Подробно — в разделе «Обучение новичка». Лучше сделать до того, как звать друзей.
   - [ ] Новый человек без объяснений за 5 минут проходит цикл «заработал → потратил» и настраивает приложение под себя

Самые важные тесты — на бэкенде: начисления, покупки при нехватке монет, двойной штраф, генерация на границах периодов.

## Обучение новичка

Цель — чтобы новый пользователь за несколько минут понял главную петлю «квест → золото → таверна» и настроил приложение под себя. Учим делом, а не текстом: каждое объяснение привязано к действию.

**1. Приветственный свиток.** При первом входе — модальное окно из 3–4 страниц с кнопками «Далее» и «Пропустить»:

- Идея: «Любишь кататься — люби и саночки возить». Развлечения стоят золота, золото дают квесты.
- Квесты: тир задаёт награду и штраф, срок, провал списывает штраф, баланс может уйти в минус.
- Таверна: меню своих развлечений, заказать можно, только если хватает золота.
- Повторяющиеся квесты: появляются сами по расписанию.

Последняя страница ведёт к обучающим квестам.

**2. Обучающие квесты.** При регистрации на доске появляется цепочка обычных квестов без срока и без штрафа, с небольшой наградой. В сумме её должно хватить на первый заказ в таверне. Они **закрываются автоматически**, когда пользователь делает нужное действие: кнопку «Сдать квест» у них не показываем, иначе их можно сдать не глядя.

| Обучающий квест | Закрывается, когда |
| --- | --- |
| Впиши первое развлечение в меню таверны | Создана трата |
| Повесь свой первый квест | Создан обычный квест |
| Сдай любой квест | Выполнен обычный квест |
| Закажи что-нибудь в таверне | Совершена покупка |
| Заведи повторяющийся квест | Создан шаблон |
| Загляни в устав гильдии | Открыта страница настроек |

**3. Подсказки на месте.** Пустые состояния объясняют, что делать дальше (частично уже есть). У непонятных терминов (тир, штраф, повторяющийся квест, «в минусе нельзя заказывать») — значок «?» с коротким пояснением.

**4. Справочник путника.** Отдельная страница с ответами на частые вопросы:

- когда списывается штраф;
- когда появится повторяющийся квест и почему не сегодня;
- почему задним числом квесты не создаются;
- часовой пояс;
- поправка казначея.

**5. Повтор.** В настройках — «Пройти обучение заново»: снова показать свиток и вернуть незакрытые обучающие квесты.

Что нужно в схеме и API:

- `users.onboarding_seen_at TIMESTAMPTZ NULL` — свиток показан. Миграция ставит текущее время всем существующим пользователям, чтобы свиток не всплыл у тех, кто уже пользуется.
- `quests.tutorial_key TEXT NULL` + `UNIQUE (user_id, tutorial_key)` — какой шаг обучения. Обычные квесты — `NULL`.
- Бэкенд закрывает обучающий квест в той же транзакции БД, что и действие-триггер: обычное начисление награды через `economy.record_transaction`.
- `POST /me/onboarding/seen`, `POST /me/onboarding/reset`; шаг «загляни в настройки» — `POST /me/onboarding/visit` с ключом страницы.

Открытые вопросы:

- Сколько золота за обучение: по 10 за шаг (60 всего) или больше, чтобы сразу ощутить таверну?
- Давать ли стартовое золото без квестов или пусть первый золотой будет заработан?
- Тур с подсветкой элементов интерфейса (вроде driver.js) — нужен ли поверх свитка и обучающих квестов, или это перебор?

## После MVP

Схема уже готова к этим функциям, менять её почти не придётся.

| Функция | Что уже есть | Что добавить |
| --- | --- | --- |
| ~~Таймер трат~~ | Сделано: `reward_sessions`, плашка в шапке | Push-уведомление об окончании (с PWA) |
| Уведомления | `due_at`, `timezone`, PWA | Таблица push-подписок, pywebpush, задача напоминаний |
| Статистика | `transactions` | Графики заработка и трат по дням |
| Отмена выполнения | Журнал транзакций | Обратная транзакция, `status = active` |
| Льготный период штрафа | `penalty_applied` | Поле `grace_minutes` в тире или квесте |

Решённые вопросы:

- UI-библиотека — **Naive UI**.
- Хостинг — **VPS** (есть у автора): Docker Compose + Caddy с автоматическим HTTPS.
